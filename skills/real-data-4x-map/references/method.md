# 做法拆解

## usaciv 是怎么做的(2026-11 公开版,从其网页与数据文件观察)

- 静态站点:`index.html` + ES 模块 + `data/*.json`(world、cities、states、counties、lenses、resources、sources、nation),canvas 绘制,无框架。
- `world.json`:六边形网格(按列行展开的平铺数组),每格存所属州/县、海拔、水域类型(海/浅海/湖)、起伏、土地覆盖、各类占比;
  另有 `tables`,**每个分类都带一句 rule 文本**(例如「7 个采样点中至少 4 个在陆地上」)。
- 产出:粮食=农业就业,生产力=制造+建筑+采矿就业,金币=GDP,科技=专业科研+信息业就业,文化=艺术就业。
- 城市=都市统计区(524 个),带分行业就业与 GDP、增长、排名、同类城市;区域来自产业专精;奇观按游客数(国家公园)与研发经费(大学)评。
- 资源:核电、水电、煤矿、金矿等,每类写明阈值与来源。
- 31 个数据源,每个带发布方、许可、用途、年份。

## 本实现(欧洲)的取舍

| 方面 | 做法 | 理由 |
|---|---|---|
| 投影 | 兰伯特等积方位(中心 10°E 52°N,球面近似,单位 km) | 等积 ⇒ 每格面积相同,格数可直接比面积;欧洲官方也用 EPSG:3035 |
| 格子 | 尖顶六边形,外接圆半径 16 km(格心距约 28 km,单格约 665 km²) | 欧洲约 8400 格有数据陆地;再细则许多 NUTS3 只有一两格也无意义 |
| 归属 | 格心 + 6 点采样,≥4 点在陆地才算陆地;多数票决定地区 | 与 usaciv 相同的稳健做法;岸线不会锯齿乱跳 |
| 小岛 | 面积 ≥120 km² 却没分到格的地区,把最近的海格补成它 | 否则马耳他等会整国消失 |
| 地区 vs 城市 | 产出挂在 NUTS3 地区,城市显示其所在地区的产出 | 欧洲没有像美国 CBSA 那样统一、带分行业数据的都市区 |
| 细分行业 | 缺报时按「父类 × 本国比例」估算并标「估」 | 不少国家 NUTS3 只报到大类;不估则一半地区没有科技、文化 |
| 地貌 | 大区内按 LUCAS 土地覆盖比例分配名额,平滑噪声排序 | 没有可直连的高分辨率土地覆盖;比例真实、单格示意 |
| 迷雾 | NUTS 之外的陆地(英国、乌克兰等)只画地形,压暗 | 地图不留白洞,同时诚实表明无数据 |
| 城市 | 维基数据人口 ≥10 万,7 km 内同名条目只留维基链接最多者 | 同一城市常有城市本体、都会区、行政单位多个条目 |

## 换地区时要改的地方

1. `sources.mjs`:`BBOX`、数据源列表。
2. `grid.mjs`:投影中心(取地区中心经纬度)、边界文件读取(字段名 `NUTS_ID` 等换成新边界的)、格子半径。
3. `build.mjs`:统计数据解析(Eurostat 的 JSON-stat 解析器可换成 CSV)、行业代码到产出的映射。
4. `rules.mjs`:国名中文表、区域阈值(先跑一次打印分布再定)、透镜列表。
5. `check.mjs`:对账口径、抽查城市清单。
6. 网页一般不用改,除了 `index.html` 的标题与百科「关于」页文字。
